# 完整模型工作流

## 1. 设计与交付契约

记录唯一认可图/PSD 的路径、哈希、尺寸、色彩/alpha 背景和初始姿态。确认画风、眼型、发型、服装、相对比例，不以“更精致”替代忠实还原。明确是头像、半身还是全身，以及眼球追踪、表情、嘴型、头身转动、四肢、物理和目标格式的实际范围。

建立部件/参数/动作清单和未完成项。不要用节点数量、参数数量或“有这个命令”代替功能证据。软件/资产授权和仓库依赖约束沿用用户环境，不在未经授权时安装编辑器、接入外部服务或引入闭源运行库。

## 2. 原坐标拆层与隐藏区域

可见像素尽量保持源图坐标；图层裁切只改变纹理局部原点，不独立缩放。将画布留白表示为统一平移，避免每个部件各自补偿。

常用部件不是固定模板，按实际设计拆：

- 后发、侧发、刘海、帽子/发饰；被脸、肩、手、身体和衣物遮挡的发束要补全。
- 脸底、眉、眼白、完整虹膜/瞳孔、上/下睑；虹膜不要随眨眼压扁，眼孔遮罩负责遮挡。
- 嘴内部、唇线/闭嘴、舌/齿等必要口型；脸底不能残留旧嘴。
- 颈、躯干、衣物、袖、上/下臂、手、裙摆、腿、鞋等实际可动结构；断开处有隐藏接合余量。

逐层 solo 检查：是否带入其他部件像素，是否仍有原位手、眼、嘴或衣物轮廓，材质是否在遮挡对象移开后连续。通过“暂时隐藏前景层”看后景，不只看自然拼合图。

### 【铁律】完整组件严禁手绘，必须走图像生成

任何完整的新状态组件或大面积隐藏补画，**严禁由代理自行手绘、拼接粗劣色块或用代码算法硬算线条**，**必须走图像生成管线**：

1. **适用资产范围**：
   - 闭眼状态（`eyes-closed`）、半闭眼（`eyes-half`）、笑眼/眯眯眼（`eyes-smile`）；
   - 张嘴口型内部（`mouth-open` / `speaking-mouth`）；
   - 面部去眼去嘴底面（`face-underlay`）；
   - 完整躯干与被遮挡衣物（`torso-underlay`）；
   - 完整长后发（`back-hair-complete`）；
   - 特殊手势或肢体态。
2. **生成调用规范**：
   - 必须以唯一认可的原图或标准局部裁切作为图生图（Image-to-Image / Edit）输入，选用 `precise-object-edit`、`inpainting` 或 `identity-preserve` 分类；
   - 严格约束生成指令：“仅修改目标局部（如闭眼），保持其余像素、脸型、线稿粗细、赛璐珞阴影与构图完全不变”；
   - 导出为带真透明通道（alpha transparency）的高分辨率素材，在工程中对齐源坐标，严禁把生成结果任意平移放大或让画风偏离底稿。
3. **严禁算法硬捏**：
   - 禁止直接将睁眼睫毛图层在 Y 轴单向数学压扁（如 `* 0.28`）并套用二次抛物线去生造闭眼或笑眼；
   - 睁眼睫毛带有厚重眼线、拱起弧度与向上毛尖，闭眼眼线则需要优美下垂（`︶`）或新月弧（`⌒`）的完整线条与羽化。强算只会产生条形码般破碎的僵硬黑杠，且导致眼窝上方失去衬底透出背景空洞；
   - 新状态组件必须作为独立图层或覆盖层接入，在参数变化时通过透明度（`opacity`）实现自然平滑的渐变过渡（Sprite Swap）。

隐藏补画保留为独立素材/层。先对齐源坐标再使用，记录仿射变换、匹配内点与残差。既有素材能满足需求就复用；需要生成时明确只补缺失材质、不改变可见轮廓。不能将整张生成图直接替换原画。

不要把不透明材质意图等同 `alpha==255`。覆盖不足与真实透明设计分开判断；半透明原像素后直接加新材质会改变自然姿态。需要语义遮挡时复用编辑器的遮罩机制，检查多遮罩并集、孔洞与反向裁剪；透明布料保留真正的透光，不套二值遮挡。

决定重叠余量时考虑最大运动与相邻部件的相对位移，而不只考虑静态接缝。隐藏区域可以超出原来可见区域，但不能在原姿态越过遮挡对象泄露出来。做区域对比，不以全图平均误差稀释小而明显的脸部错误。

## 3. 网格

使用现有网格生成、细分和拓扑工具。关节、弯曲处、嘴眼与遮挡边缘需要可控密度，平坦的大区域不用等密度堆点。

`earcut` 是多边形三角剖分工具，不是高质量 Delaunay 网格生成器；一堆狭长轮廓点和随意 Steiner 点可能产生容易翻面的细长三角形。规则网格适合连续材质，但不能替代真正的材质分层和接合。

UV 以纹理实际裁切/图集坐标定义。新增顶点应落在包含它的三角形中并插值 UV；“离三角形质心最近”不能证明包含关系。编辑拓扑后同步已有关键形态偏移、morph/glue 索引，验证 UV、索引和顶点缓冲都更新。

每个参数样本比较三角形有向面积与自然姿态，检查翻面、退化、异常拉伸和 deformer 越界。透明网格矩形包围盒与真实不透明像素范围不是同一件事；不要用夹紧顶点来掩盖边界设计问题。

同一父变形器不保证两张不同网格在拼接处采样一致。非线性 warp 后，栅格器在各自三角形上作仿射插值；源图和隐藏支撑宜共用 rest-space 网格/裁切范围，或者显式测量接合面的采样误差。几何一致只解决贴合，不解决补画颜色或纹理连续性。

遮挡 coverage 也要贴在同一表面。支持纹理 alpha 遮罩时，让 coverage 与对应原图部件共用 vertices、indices、UV 和运动；仅以白色几何轮廓独立采样，细分后仍可能在非线性变形中错位。零 drawable opacity 的 mask 仍提供纹理覆盖，多张 coverage 用 alpha 并集合成，再执行正向或反向裁剪。扩张遮罩的余量要通过自然姿态和动态边缘共同校准。

## 4. 变形树与参数

先组好职责：全身/身体、呼吸、颈/头、局部眼眉口、头发/衣物、上/下肢/手。只让部件继承应该继承的运动，避免身体、头部和局部节点重复施加同一旋转或物理。

以下是职责示例，不是强制节点名称或现成工程模板：

```text
body pose / breathing
  head roll
    face XY
      eye aperture + sclera / iris / lids / brows
      front hair root + secondary sway
    mouth anchor following the face + local open/form
  neck / torso / skirt
  arm attachment -> limb deformation -> wrist/hand
  leg attachment -> limb deformation -> foot
  back hair root + secondary sway
```

头发根部跟随谁、裙摆/腿是否使用局部 warp、口型是否需要脱离全脸剪切，由角色和动作需求决定。逐参数测出受影响的部件；保留旧参数/变形器数量不证明重建后的网格仍正确受控。

位移、旋转、透视、开合与表情应能分别检查。以实际参数 ID 和范围工作，不假设显示名称或标准名字必然存在。复制旧绑定前确认新网格的顶点数、顺序和坐标系匹配。

关键形态先做自然姿态和单轴，再组合角点和中间值。验证眼孔/瞳孔对齐、左右眼独立开闭、无双套睫毛的连续眨眼、嘴中心锁定、嘴形状与开度组合、下颌/颈部遮挡和深度换序。

眨眼与表情开合的绑定逻辑：闭眼时（`ParamEye*Open = 0`）应让睁眼睫毛与虹膜淡出、闭眼素材淡入，下眼眶底层由完整的面部皮肤衬底承托，确保无任何接缝或透色。笑眼（`ParamEye*Smile = 1`）同样应采用专属的柔和新月弧形素材，不可靠把压扁的睫毛二次向上弯折来伪造笑意。

头部转动会露出颈部和侧发根；自然姿态被下巴/围巾遮住的区域也必须是完整材料。补嘴而不查头颈接合，可能只是把一个缺陷转移到另一个区域。

对嘴等小部件，使用脸部相对锚点或局部刚性框架。若从大脸 warp 分离，必须烘焙/绑定头部位移并保留真正的头部滚转，不能简单改父节点让嘴不再跟头。测量不同头部姿态下的中心误差和额外角度，而不是只在初始姿态摆正。

## 5. 物理、动作与嘴同步

基础手动关键形态通过后再加物理。记录输入、归一化、输出范围、反射、FPS、时间步长和初始状态；动态求解与已烘焙输出只能选择一个施加者。检查输出是否越过参数声明范围，不能靠未说明的夹紧掩盖问题。

至少提供自然待机和诊断动作。待机展示真实常用运动；诊断动作覆盖较大头身转动、双眼/单眼眨眼、视线、口型组合、四肢和物理。不得删掉问题帧、缩小参数范围或关闭必要部件以伪造通过。

身体和四肢动作是按用途选配，不是“模型完整”的必要展示方式。胸像/桌面陪伴等普通预览可固定躯干、四肢、裙摆和围巾，只保留头部、眼眉、口型与低幅发丝运动；保留独立诊断动作和可编辑控制器。检查动画排序与默认选择，避免把夸张诊断排成默认待机。改驱动轨道后用原有物理烘焙接口重算，不能沿用旧输出或播放时再叠一次实时物理。

嘴同步只有在与实际音频/目标输入测试后才能称为同步；无音频的预设开合要标为口型演示。输出视频按真实采样 FPS 编码，检查持续时间、解码帧数、分辨率和非静止内容。

对烘焙输出先检查每一帧的原始数值，再检查求值后的外观。插值器在关键形态域外的夹紧可能让超范围轨道“看起来正常”，但会截平物理反弹；修正输入归一化/输出比例并重新烘焙，而不是偷偷截断旧诊断动作来使报告通过。

## 6. 导出与可编辑交付

保存模型与所有相对纹理资源，必要时保留分层 PSD、可复用模板、参数/部件映射、动作和物理数据。运行包应包含清单引用的全部资源，图集 UV 与纹理索引一致。

对导出包执行回读和渲染对比，不只检查文件存在或 ZIP 能解压。实际目标运行环境的兼容性另外验证；不能用工具的自述或一次同源解析成功代替外部兼容性证据。

最后从干净环境重新打开可编辑包，核对工程/纹理哈希、自然姿态和代表动作。说明哪些素材是原像素、哪些是隐藏补画，保留未解决事项。验收细项见 [acceptance.md](acceptance.md)。

工程 JSON 与纹理一起组成模型版本。修改 PNG 可能完全不改变 JSON 哈希；验收缓存、视频、回读包须同时核对纹理内容，不能只比较工程文件。图集回读还要在小输出画布上检查远离图集原点的 UV 区域，避免低坐标样本掩盖采样故障。
