# 验收门槛

## 建立证据，不建立“漂亮截图”的结论

每次验收记录项目/纹理/底稿哈希、参数、动作帧、FPS、渲染器、画布/截图缩放、背景、物理模式和结果路径。工程被保存或资产更新后，旧报告不能自动沿用；对几何/纹理不变的元数据改动也明确记录。

缓存有效性须包含资源内容：JSON 哈希相同不代表 PNG 相同。使用 `projectSha256 + textures[{id,path,sha256}]` 形成 revision，并让 GUI-only、视频和回读报告明确对应该 revision。

| 门槛 | 必需证据 | 失败时不能宣称 |
| --- | --- | --- |
| 原设还原 | 同坐标的自然姿态与认可底稿；眼嘴/头发/服装等局部指标及人工并排检查 | “角色已还原” |
| 语义拆层 | 每层 solo；前景移开后后景完整；无原位手眼嘴/其他材质残片 | “完整可动部件” |
| 组件生成合规 | 闭眼、口型、底面等新状态组件必须来自图像生成管线，严禁手绘或算法伪造眼线 | “组件风格与原画统一” |
| 数值安全 | 拓扑、引用、三角形方向、参数/物理范围、遮挡和中间值检查 | “绑定可靠” |
| 动态外观 | 全身和脸部真实连续动画；无露底、重影、浮嘴/额外歪嘴、断裂、突跳 | “动态验收通过” |
| 实际编辑器 | 打开、纹理就绪、控制响应、同帧截图、保存重载、代表窗口尺寸 | “GUI 正常” |
| 输出闭环 | 包内引用、真实纹理尺寸、UV、回读渲染、可编辑包重新打开 | “导出包可用” |
| 目标兼容 | 明确目标环境与真实运行结果，不引入违背项目约束的运行依赖 | “目标播放器兼容” |

## 像素与几何

- 先统一尺寸、原坐标、固定平移、alpha/背景和色彩转换，再做 MAE/最大误差、超阈像素比例、轮廓/锚点比较。相位相关等亚像素估计应说明算法与自相关基线，不把估计精度当作不可证实的绝对精度。
- 眼睛/嘴很小，不能只报全图平均误差。检查实际虹膜位置、眼角方向、睫毛和眉毛，而不是仅检查参数值。
- 确定阈值时考虑用户目标和栅格器；某一案例的 `2/255` 或 `0.004 px` 不是所有项目的标准。
- 自然姿态像素近乎相同仍可能是错误拆层；连续动画是独立门槛。
- 压缩视频用于看动作，不用于像素金标准。使用原始 PNG 和明确的背景比较色彩/alpha。
- 同时检查关键点和补间：头部 XY 网格、Z 滚转、身体组合、眼开度 0/中间/1、视线极值、嘴形状 × 开度、物理极值和 limb/body/hair 相对位移。

## 嘴与接缝专项

测嘴中心到脸部锚点的偏移，及嘴轴相对真正头部滚转的变化。分离纹理自带歪斜、口型曲线的非对称、头部 warp 剪切、网格采样不一致和坐标系错误。修复必须保住自然姿态，不靠把嘴钉在画布坐标解决跟头运动。

底稿本身可能倾斜，不能以画布水平作为嘴轴金标准。记录眼中心/鼻/下巴等解剖坐标，比较口型实际墨迹的轮廓、加权质心与主轴；小嘴原生像素少，可另做高分辨率实际重渲染以降低量化影响，但仍检查原生 GUI 与连续视频。曲率、开度和视角会改变主轴估计，必须声明测量域和误差而非要求所有形状数学零误差。

眼部要分别检查虹膜上半部/高光的归属、眼白边缘的皮肤/侧发污染，以及眼孔遮罩是否连续。颜色阈值只能帮助定位；深紫色阴影和黑睫毛相近，白高光又可能属于虹膜。视线极值与开度中间值共同复现，避免在自然姿态完全盖住错误。

眼孔还须与认可原图的眼睑边界相符。不能把不同连通成分的凸包当眼孔，不能为静态纹理不被裁切而随意放大白底。动视线后，眼白不得改写侧发、脸外或眼睑外的像素；“没刷到头发”和“没有扩张到脸颊”是两个检查。用原图逐像素归属、同一脸面上的头发遮挡、自然到非零视线的连续视频共同验证，不把全图误差稀释成通过。

做有/无眼部或开/闭眼的侧发贡献对照时，优先比较同一实际渲染器的输出。CPU 可定位 source-space probe，但 GPU 场景与 CPU 反事实之差还包含两种栅格器误差，不能直接归因于眼睛越界，也不能简单放宽阈值掩盖。必须说明 probe 覆盖的是可信侧发内部，不代表所有脸外边界已经测完。

闭眼线条与生成组件合规验收：

1. **严禁算法硬捏闭眼**：闭眼（`ParamEye*Open = 0`）与表情状态下，眼线必须展现自然下垂（`︶`）或新月形（`⌒`）的高精度二次元手绘质感（带自然毛尖羽化、眼角飞羽与双眼皮折痕），绝对不得呈现由于数学粗暴压扁（如单向缩放 0.28）造成的条形码状断裂粗黑杠；
2. **强制复用生图资产**：工程中已由生图管线产出专用闭眼或特殊态素材时，必须直接复用该素材并通过透明度平滑过渡，严禁由代理自行手绘、拼凑色块或算法拟合伪造线条；
3. **眼窝面部平滑承托**：闭眼时整个眼窝区域必须由完整连续的面部皮肤衬底承托，严禁由于衬底过度裁剪或未闭合导致露出背景白底空洞。

接缝检查应包含抬臂/手腕、摇头/发丝、围巾/裙摆与身体。自然拼合必须没有隐藏补画泄露；最大相对位移必须有足够隐藏覆盖。保留失败帧和前后对照，不能只挑最自然的姿态。

## GUI 与编码

先暂停播放、清除表情、关闭自动待机；若输出轨道已烘焙物理，关闭实时物理。设置完整参数状态/明确帧后，等待真正的目标帧已绘制，再截图。任意固定睡眠不能证明一致性。

验证立即截图与稳定后截图相同、GUI 与离线渲染在允许的栅格差异内一致；记录运行错误与未修安全警告。视频用 `ffprobe` 等成熟工具检查解码帧数、帧率、时长和尺寸。不要仅以文件非零大小判成功。

## 结果表达

对每一门槛标明 `通过 / 失败 / 未测`。交付工程和可播放预览，列出影响使用的剩余问题，不淡化大面积露底为“边缘小瑕疵”。阶段成果与完整模型区分；工程/包/视频的哈希要可对应。
