# 踩坑与验证账本

基于 L2DEditor 实际项目，记录日期 2026-10-14。坐标和阈值只是该案例证据，不是所有角色的模板。新发现按同一结构追加；修复后更新状态和回归证据，不删除仍有意义的失败原因。

## P01 原设计漂移：拆层时重画了眼睛和头发

- 症状：自然姿态眼型、眼角方向、刘海分缝、侧发和后发轮廓与认可图不一致。
- 根因：生成孤立部件后独立缩放到手工框，误把“能控制开闭”当作“眼睛还原正确”。
- 修正：锁定唯一底稿/哈希，以原图坐标提取可见像素；补画只作隐藏支撑，生成素材先配准。
- 回归：分眼/头发区域像素差、锚点/方向和并排检查。案例自然姿态眼部 MAE 从约 38/45 降至约 0.023/0.026，最大通道差 2；这不证明动作通过。
- 状态：静态还原已验证。完整动态仍需独立门槛。

## P02 静态互斥分区不是完整可动层

- 症状/复现：`lavender-aligned` 的 `showcase` 帧 308 抬臂时腋下后发大面积露底、原位手残影；`idle` 帧 36 也有接缝。
- 根因：源图可见像素虽完整分配，但隐藏头发/衣物没有补全；前景位移后原来被遮挡的地方变成空洞。
- 修正方向：语义重分层，重建完整隐藏部件并留相对运动余量；原姿态必须由前景遮住新支撑。
- 回归：移开前景、层 solo、最大 limb/body/hair 相对位移和全动画逐帧暴露检查。
- 当前修正：v2/v3 新增隐藏支撑和同面采样；v4 清理旧标签、采样真实发根、补齐隐藏颈圈并重新做隐藏后发。真实 GUI 帧 68 的颈圈大块露底已收敛，帧 308 的主要深色残片减少；后发笔触/材料接缝与部分细边仍未全部通过。
- 状态：部分修复，动态接缝未全部通过。不得以自然姿态差分为 0 宣称完成。

## P03 颜色阈值把肢体/材质拆错

- 症状：身体层包含原位手指、袖子窄条、发丝和围巾残片；运动后多一只手或双轮廓。
- 证据：`source_body.png` 的 solo 图片直接显示残片；仅凭紫/蓝色阈值不能区分发丝阴影、衣物和抗锯齿边缘。
- 修正方向：位置/解剖先验与成熟分割工具结合，补查手指轮廓和暗线；颜色用于候选，不作最终语义。确认单个部件没有借走邻近发丝。
- 回归：所有手像素/轮廓只跟随对应手臂；身体/后发 solo 无手部残片，抬臂无旧位置残影。
- 当前修正：使用解剖区域、材质种子与 OpenCV GrabCut，额外核对手指/袖边和侧发；身体层的主要原位手残片已移走。v3 回收了身体层中的后发/裙边发束、高光归入对应发层，并移走了手臂中的主要围巾条；分割顺序问题见 P19。
- 状态：代表抬臂帧的手部残影已改善；暗发丝/围巾碎片的完整语义归属仍需逐层查，不宣称所有图层已完美。

## P04 摇头时嘴歪

- 症状：小口型在头部运动时产生多余倾斜、剪切或相对脸部的漂移。
- 已测原因：原绑定在头部 Z/body 滚转为 0 时，XY 姿态带入约 ±2.73° 的嘴部角度，嘴中心与实际渲染脸面最大偏差约 0.38 px。头部 warp 剪切与大小网格采样差异不能仅靠“同一父节点”排除。
- 修正方向：先测量，再做跟随脸部锚点的局部口型框架；头部滚转和开合/嘴形分离。不能简单移到画布根部或仅在初始姿态摆正。
- 回归：头部 XY/Z × 口型开度/形状组合的中心误差、额外角度和脸部特写连续视频；自然姿态保持原图。
- 当前修正：从 Rust/Wasm 求值后的真实头部 UV 面采样锚点，将位移烘焙为局部口型 warp，父节点保留真正头部滚转但不继承 yaw 剪切。仅构建阶段使用少量核心网格插值；未另写运行时求值器。旧嘴的抗锯齿背景与口型资产分离。
- 回归数据：81 个头部 XY（含中间键）样本，open=0.7/form=0/Z/body=0，最大锚点误差约 0.00027 px、额外角度约 0.00054°。
- 状态：该几何专项已验证，其他口型/开度/身体与滚转组合及视觉动作不能由这 81 个样本自动宣称通过。

## P05 狭长三角形在动作中翻面

- 症状：转头时刘海/帽子横向破碎，摆臂/后发出现条状错位，自然姿态正常。
- 根因：轮廓/Steiner 点形成细长三角形，经非线性变形后翻转；“有三角剖分”不代表质量可用，earcut 不是 Delaunay 自动网格。
- 修正：复用规则网格/合理细分并检查实际关节，避免把各部件按非线性坐标框拉伸。
- 回归：相对自然姿态有向面积，端点、中间与组合姿态；还要看接缝，数值不翻面不代表没有露底。
- 回归补充：v3 的 288 帧 idle、384 帧 showcase、144 帧 wave，共 816 帧可见网格未发现相对自然姿态的翻面。零透明度遮罩、其他参数组合及异常拉伸仍不能由此自动推断。
- 状态：所测样本/动作的可见网格方向已验证，动态接缝仍未通过。扩展隐藏覆盖后也要 lint 父变形器范围；本例额外 padding 曾造成 30 个网格点越界，调整实际覆盖范围后消除，未夹紧可见顶点。

## P06 零透明度遮罩被剔除，瞳孔失去遮挡

- 根因：求值器跳过透明网格，忽略其仍被其他网格引用为遮罩。
- 修正：Rust/Wasm 与 JS 保留被引用的零透明度几何，渲染时不画该源；眼孔随开度变化，瞳孔不压扁。
- 回归：透明遮罩的裁剪效果与不绘制本体、JS/Wasm 一致、普通透明节点仍被剔除。
- 状态：代码与包含这两类断言的专项回归已验证。该编辑器的 `visible:false` 与 `opacity:0` 不是同一行为，见配套 MCP skill。

## P07 三角拼缝与重复 alpha 不是切割错误

- 症状：离线纹理重复变深、透明边/遮罩内部出现细缝。
- 修正：复用 Canvas/Skia 合成能力；网格纹理先离屏合成、drawable opacity 只施加一次，遮罩用边界而非每个内三角单独 AA。
- 回归：半透明纹理、内边接缝、凹形、洞/多岛、反向与多个重叠遮罩分别测。本轮额外验证重叠反向并集、单遮罩孔洞和复杂 PathOps fill rule；见 P16。
- 状态：已验证所列案例；一般遮罩完整兼容、翻面/自交几何仍需专项。

## P08 状态更新了，但截图还是上一帧

- 根因：React 控制器 effect 比编辑器状态晚一次提交，旧控制器的 `frameRendered:true` 可能指旧帧。
- 修正：`hasRenderedFrame(expectedFrame)` 比较目标求值帧与实际绘制帧，不能只看参数/state/任意 sleep。
- 回归：9 种静止状态立即截图与延迟截图 RGB 差为 0；GUI 自然姿态与离线差约 0.000002。
- 状态：已验证。连续播放时截图属于最新已绘制帧，不能声称一定是某个未暂停的逻辑帧。

## P09 补画尺寸相同，也可能位置不一致

- 根因：生成器重画/重构了比例和位置；把 1086×1448 文件原位放入不等于像素对齐。
- 修正：使用成熟特征匹配/配准，保存变换和内点残差；仅把必要隐藏区域投到原坐标，不能让整张补画覆盖可见原图。
- 证据：旧脸底素材需要约 0.968 缩放；SIFT/RANSAC 脸底内点中位误差约 0.62 px。
- 状态：眼部/头皮隐藏补画配准已验证；其他资产各自测，不复用这个常数。

## P10 图集成功/ZIP 完整，仍可能是空白运行包

- 症状：内部导出成功，回读后 17 个网格 `MISSING_TEXTURE_REFERENCE`，渲染空白。
- 根因：当前 importer 将纹理重命名 `tex_0`，但网格仍引用 `tex_atlas_00`；并硬编码纹理 2048 尺寸，实际图集可为 4096。
- 修正方向：正确恢复纹理索引/ID和真实尺寸，再做同姿态/动作回读渲染。
- 状态：已定位未修。不得发布为“运行包验收通过”，外部播放器兼容另测。

## P13 工具名相同，实际命令契约却漂移

- 证据：`mesh.add_vertex` 在标准命令文件中被注册两次；后一个覆盖前一个。GUI 仍传 `mesh_id/vertex`，实际 handler 要 `node_id/pos`。
- 另一个问题：后一个按最近质心选三角形，不能保证点在其中；默认 `pos/canvas` UV 对裁切/图集纹理不正确。
- 修正方向：统一唯一契约、GUI 和 CLI/MCP；插入用包含三角形并插值 UV，保持绑定/morph 偏移。
- 修正：现在仅注册 `node_id/pos/uv?` 契约；包含三角形重心权重插值 UV、关键形态和 morph，边上加点同时拆分两侧。GUI 将显示三角形映射回基础网格；重复注册直接报错。
- 状态：专项测试覆盖裁切 UV、共享边、包含面、非法输入原子回滚和撤销重做；真实 GUI 操作的验证结果另见本轮验收报告。此修正不代表其他拓扑命令已同步修复。

## P14 FPS、物理和视频可能掩盖问题

- `renderAnimationSequence` 当前 `fps` 选项只改变编码帧率，不重采样轨道。24fps 的 288 帧若按 30fps 编码，会从 12 秒变为 9.6 秒。
- 已烘焙物理轨道不要再开实时物理；输出也要检查参数范围。v3 全帧检查发现 `showcase` 的 `ParamHairSideL/R` 各 27 帧超出 [-1,1]，首帧 77，极值达到约 ±1.698；关键形态域外夹紧不等于轨道本身正确。
- MP4/YUV 的颜色与 PNG 不能作逐像素等价比较；播放视频检查动作，原始 PNG 检查像素。
- v4 修正：左右后发 output `angle_scale` 从 0.2 校准为 0.1，使用既有 Rust/Wasm `bakePhysicsToAnimation` 重新烘焙三个原驱动动作，未截断旧曲线/删除帧。
- 状态：v4 三个既有动作的 816 个视频采样帧已无超范围值。任意突变的实时输入、其他 FPS/驱动轨迹仍未由此证明安全；重采样能力不能虚报。

## P15 “opaque” 图像内部 alpha 不一定是 255

- 症状：已有隐藏身体素材与待补区域有约 4 万个像素重叠，但用 `sourceAlpha === 255` 筛选后一个也没有。
- 根因：生成/导出素材内大量衣物像素 alpha 为 241..254；其视觉材质意图与实际 alpha 数值不能混为一谈。直接加背景支撑也可能透过前景改变自然姿态颜色。
- 修正：按实际语义制作独立遮挡 coverage，继承同一部件的运动，隐藏支撑位于其后并使用反向并集裁剪。保留源图 alpha/颜色，不以任意改阈值或在自然姿态关闭支撑伪造通过。
- 回归：隐藏支撑确实有覆盖、自然姿态仍过像素门槛、移动前景后有完整材质。阈值仅是该素材的 mask 候选策略，透明布料/玻璃不能当成不透明衣物套用。
- 状态：v2 已实施；材质融合和所有暴露状态仍需视觉检查。

## P16 反向遮罩必须先并集，Canvas 填充规则必须显式

- 根因一：把画布矩形加多个 mask 然后 `evenodd`，重叠遮罩会 XOR，反而从重叠区漏出。
- 根因二：Skia PathOps 的复杂差集可能保留 even-odd 轮廓；`ctx.clip(path)` 的默认 nonzero 不自动沿用 Path2D 的 fill type。实际颈部支撑因此在自然姿态泄露 373 个像素，最大通道差 140。
- 修正：成熟 PathOps 对每个几何 coverage 做 Union，再对画布 Difference；结果显式 `clip(path,'evenodd')`。不要自写多边形布尔运算。
- 回归：重叠反向遮罩、单遮罩孔洞、复杂多个带洞 coverage 的小型复现；案例自然姿态恢复为最大通道差 2。
- 状态：v4 加上 P27 后 6 个遮罩专项测试通过，当时完整测试为 24 个 Rust、42 个 Vitest。v5 经 P31/P32 改为纹理 alpha 流程，最新为 24 个 Rust、51 个 Vitest，含 9 个遮罩与 6 个运行包/图集案例。十二个 GUI 状态立即/稳定后截图一致；复杂姿态的 GUI/离线仍有边缘栅格差异，不能宣称逐像素完全相同。

## P17 配准内点少/分布窄时，矩阵看起来合理也不能信

- 证据：旧完整后发只有 2 个可靠匹配；旧 arms 仅 3 个匹配且估计缩放接近 0。某 body-v2 的 13 个内点集中在约 50px 的纵向带，不能证明整个上身都对齐。
- 判断：拒绝这类“零残差”的退化/局部拟合，检查内点数、覆盖、矩阵尺度/行列式和重要锚点。隐藏身体采用另一个有 16 个内点、约 336px 纵向覆盖的既有素材，并限制用途。
- 新后发：内置生图只补缺失材料；输出实际轮廓仍超出请求坐标。隐藏-only 的 alpha-bounds 映射明确标为人工覆盖映射，不冒充恢复了原画像素对应。可见原发保留。
- 状态：资产选择/拒绝和变换已记录；新暴露材质的自然连续性仍需作者/视频验收。

## P19 分割保护区覆盖了先前的可信种子

- 症状：改用 GrabCut 后，围巾长条仍附在手臂上，抬臂时像多出一条围巾。
- 证据：源坐标 `(640,500)` 的 RGBA 约 `[100,110,192,252]` 是围巾，但 v2 标为右臂。代码先设置围巾 foreground，再将所有先前 arm 标签设为 definite background；后一步直接覆盖前一步。
- 修正：不能把粗分标签自动升级为保护区。依据局部解剖、皮肤与真实前发保护，允许新的围巾判定纠正旧手臂归属；检查写入顺序、BG/FG 冲突和分割回写是否确实替换旧分类。
- 回归：solo 原图切片、追踪失败坐标、抬臂帧 308；亮发高光也必须随对应发层，而不能因颜色阈值失配留在脸底。
- 状态：v3 的主要围巾条归属与发高光已修正。薄边/暗线和少量残片仍需语义清理，不能推广为全图拆层完成。

## P20 共用父节点不等于共用渲染表面

- 根因：源图层、裁切的隐藏层和 contour mask 有不同网格；同一非线性父 warp 只映射各自顶点，三角形内部的仿射采样并不相同。P04 的小口型是另一实例。
- 修正：v3 源后发/隐藏后发、源身体/隐藏身体分别共用原坐标裁切范围、rest vertices 与 indices；UV 仍指各自对应纹理。遮罩必须另外检查，不能因为 parent 相同就认为其 coverage 完全贴合。
- 回归：相同位置的实际求值表面/接合边、纹理边、头身组合和完整运动；不要只比较节点父链。
- 状态：上述两组支撑的网格一致性已实施，81 个嘴部 XY 样本专项通过；补画材质连续性和所有遮罩的面采样尚未全面通过。

## P21 隐藏补画的透明 RGB 被当成有效颜色

- 症状：对隐藏过渡作 OpenCV inpaint 后，中间版本摇头/腿间出现黑色条带，自然姿态像素验收却仍通过。
- 根因：素材透明区域的 RGB 为 0，被当作已知邻域；之后将过渡区域 alpha 恢复为不透明，就把这些黑色“未知颜色”显示出来。只修改 RGB 而不跟踪 alpha 的有效性会污染补画。
- 修正：以实际素材 alpha 和可信原发像素确定已知材料，将所有未知 RGB 与过渡区一并加入 OpenCV inpaint mask；仅对需要的隐藏覆盖恢复 alpha。原图可见像素不重画，算法填充也不冒充人工完成的发束纹理。
- 回归：最大相对位移后的暴露区域、黑/白/浅色背景和原始 RGBA；必须有动态证据，静态被前景遮住并不说明补画正确。
- 状态：该黑条已在 v3 的真实 GUI 帧 68/308 消除。隐藏补画仍有发束/线条融合不自然和接缝，整体材质验收未通过。

## P22 分割只回写前景，旧的错误标签仍留在背景

- 症状：GrabCut 已把某区域判为背景，模型仍带着早先粗多边形/颜色阈值分出的袖边、裙边和深色残片；单帧合成忠实，运动却撕开。

- 回归：逐层 solo、失败像素所属 ID、抬臂帧 308，核对前侧发尖没有被 body/back 保护区吞掉。
- 状态：新分类已实施，原图像素保真仍需与全动画分别验收；不宣称所有细边已完成。

## P23 后发根“跟头”却没有跟实际头面

- 证据：旧 `back_follow` 只绑定 AngleX/Z，缺少 AngleY，且位置变化来自独立猜测；与实际脸面 XY/Z 的运动并不相同。第一行控制点某些组合位移约 180px，不证明发根和脸面相接。
- 修正：v4 采样实际 Rust/Wasm 求值头面上的三个原坐标锚点，烘焙 XYZ 225 状态的跟随 warp；发根区域完整跟随，向下平滑过渡到身体附着。物理从发根下方渐入，不让根部随摆动漂移。
- 回归：实际头面/后发根的求值点距离、XY/Z 与身体组合、全身/脸部运动。只是 parent 或参数名相同不够，参见 P20。
- 数值回归：v4 两个发根锚点、含中间值的 Head XYZ 1,377 组样本，最大与脸面偏差约 0.11px；范围仅是 body/physics 默认，不证明全材质接缝或任意身体组合通过。
- 状态：所测发根几何已验证，动态材质接合仍独立验收，不能用嘴部 81 样本代替。

## P24 发束移开露出的缺口，其实需要围巾材料

- 症状：摇头/侧发移位后，颈圈左右出现发束形状的孔；补后发、身体或肤色仍不能自然闭合。

- 修正：内置生图补齐独立隐藏颈圈，仍使用原可见围巾。仅放到声明的原坐标覆盖区，并用当前 head/front hair 的遮挡自然隐藏；颈肤色改用已配准头颈素材的阴影，避免身体素材的亮色肤色块。

- 状态：正确隐藏颈圈资格已修正，自然姿态恢复最大差 2；当前实际 GUI 帧 68 和完整动作已重录，颈圈大块露底收敛，局部细边仍需处理，未宣称整体材质通过。

## P25 alpha=0 仍保留整个角色的 RGB

- 证据：提取后发参考只把 alpha 清零，PNG 中央 alpha 确实为 0，但其 RGB 仍是身体/脸；本轮图像查看/参考预处理仍显示了整个角色。普通编辑器合成正常，不说明传给其他图像工具的内容也只有后发。
- 修正：隔离部件参考在完全透明区域清空 RGBA；已见的部分透明边保留正常颜色。明确标注编辑目标/上下文参考，不能依赖 alpha 来隐藏不该出现在部件输入中的其他角色内容。
- 回归：检查原始 RGBA、实际合成，以及图像工具看到的目标；不能只检查透明像素数量。
- 状态：本轮参考已验证修正。不是说所有查看器或服务都忽略 alpha，也不是要求清空合法抗锯齿边。

## P26 数学上正确的 JSON 单位矩阵，OpenCV 却拒绝

- 复现：`[[1,0,0],[0,1,0]]` 经 NumPy 默认转换成 int64，`warpAffine` 报 CV_32F/CV_64F 断言，虽然形状和值都是正确的。
- 修正：从 JSON 读取仿射/投影矩阵时显式 `dtype=np.float64` 或对应浮点类型，检查 2x3/3x3 形状和有限值。
- 状态：本例已修。不能把图像 I/O 类型错误误诊为配准或模型变形错误。

## P27 共享顶点的遮罩岛被边界遍历丢掉

- 复现：两个方形只共享一个顶点，第二个方形部分被裁掉；正向和反向遮罩都可能错误，mixed winding 不是拒绝合法覆盖的理由。
- 根因：按顶点 visited 的边界遍历假设每个顶点只属于一个简单闭环，无法表示 pinched boundary。数值 lint 或单个眼孔测试不会发现。
- 修正：headless mask adapter 以实际三角形组成统一正向 winding path，复用成熟 Skia PathOps Union/Difference；不逐三角形独立 AA，也不自写复杂多边形布尔算法。
- 回归：新增正/反向、共享顶点、多岛和 mixed-winding 小型 fixture；修复前失败，修复后与既有 5 个 mask 测试一起通过。
- 状态：该 mask adapter 专项已验证。普通 drawable 的其他边界路径并未在此改动中全部重写，不能宣称所有非流形拓扑都已支持；也不能把围巾的资格错误误归为这一个 bug。

## P28 隐藏支撑被自己的扩大遮罩遮住，拼缝变成白线

- 症状：部件和支撑共用网格仍出现白色细缝；原图和新支撑严格互斥，滤波边缘合成的总 alpha 不够。额外把 own source coverage 也加入反向遮罩会扩大空隙。
- 修正方向：遮挡几何对应真正的前景，不把自身可见片扩大为支撑禁区；在原 cut 边做同材质的隐藏 underlap。v4 在近边的高 alpha 自身像素下复制原材质作约 3px 余量，两者同 rest mesh，不关闭自然姿态支撑或涂背景色伪造通过。
- 回归：自然姿态、深浅/透明背景、源可见片/支撑交界与最大相对运动；本例的 alpha/宽度只是局部校准，不适用于真实透光材质。
- 失败尝试：把 underlap 同时推广到身体后，围巾边的 19 个像素最大差升至 3；逐层关掉 body_hidden 才恢复 2。该身体 underlap 已撤回，保留通过门槛的后发余量，未放宽自然姿态阈值。
- 状态：v4 自然姿态最大差 2 已复验，完整 GUI 动作已重录，后发细缝/笔触仍未整体通过；几何同面不能替代此 alpha/材料门槛。

## P29 低 alpha 残渣被补画升级成不透明发条

- 症状/复现：v4 后发 solo 或 `showcase` 308 帧，在腿旁出现原图没有的直条；隐藏后发还保留袖口、掌形暗斑。
- 根因：过渡距离取 `labels == back_hair`，包含 alpha 1..31 的抠图残渣；随后把邻域 alpha 设成 255。错误边界被扩成真正可见材料。
- 修正：材料边界只从经语义确认的高 alpha 原发建立；生成参考另做低 alpha 噪声清理，但运行工程继续复制原可见 RGBA。本例可信种子改为 alpha >= 240，旧过渡区从 51,812 减为 44,937 像素；阈值不是通用材质标准。
- 回归：solo 源发、隐藏发、关遮罩和深色/透明背景；同时检查自然姿态，防止噪声消除偷偷改变可见底稿。
- 状态：原因已定位，v5 已实施并通过静态门槛；完整动态验收按本版纹理哈希记录。

## P30 工程哈希没变，素材已经换了

- 复现：v4/v5 换了隐藏后发 PNG，工程 JSON 仍为同一个 SHA256；只校验 JSON 的 GUI-only 流程会误用旧 CPU 截图。
- 根因：工程存相对路径和元数据，不包含 PNG 内容。
- 修正：将工程哈希和所有纹理 ID、路径、内容哈希组成 revision；复用缓存前核对整个 revision。视频、包和验收报告同样记录资源证据。
- 回归：只更换纹理、保持 JSON 不变时，旧缓存必须被拒绝；相同资源重新打开可复用相同证据。
- 状态：v5 GUI 缓存门槛、视频及回读脚本已改；不能继续沿用只有 JSON hash 的旧报告。

## P31 几何遮罩与可见纹理采样面不同

- 复现：缩窄轮廓遮罩后，v5 摇头仍有白边；独立 contour 的数万三角形还使 CPU PathOps 明显变慢。全局缩窄轮廓曾漏掉领口小岛，造成自然姿态单像素 RGB 差 31。
- 根因：独立轮廓顶点经父 warp 直接映射，原图却在自身网格三角形内插值；相同父节点与细分不能保证相同表面。轮廓过滤还会丢弃小覆盖岛。
- 修正：复用 PixiJS `AlphaMask` 和 Canvas alpha 合成；coverage 与对应可见部件共用 rest vertices、indices、UV 和运动。黑色 mask 也能有有效 alpha，Pixi 要明确读 alpha channel；多 mask 用 source-over 并集，反向再取补集。
- 回归：纹理内部孔洞、半透明重叠、正/反向、零 drawable opacity、mask 移除/Undo、网格删除/Undo，以及真实角色的同帧 CPU/GUI 对照。
- 状态：8 个 mask fixture 通过；隔离 GUI 的四个 alpha 案例及生命周期操作通过。材质没有画齐的缺口仍需单独修，不由遮罩测试自动解决。

## P32 恒定 UV 的合法遮罩在 CPU 消失

- 复现：所有顶点取 `[0.5,0.5]` 的白色几何眼孔，在新的纹理 mask 流程里变空；原有孔洞/共享顶点 fixture 失败。
- 根因：CPU 用 UV 三角形求仿射逆，UV 面积为 0 就跳过；GPU 可对整面采样同一 texel。
- 修正：三顶点 UV 相同时按同一 texel 采样并保持几何裁剪，不能把合法恒定 UV 视为坏拓扑。
- 回归：1x1 白色覆盖、半透明 texel、混合 winding 多岛、图集重映射后的恒定 UV。不能把 atlas 中的单 texel 区域直接拉伸后继续与透明邻居滤波；先取得那个点的 1x1 采样，再作恒定覆盖。
- 状态：包括恒定 atlas UV 的 9 个遮罩案例已通过；任意一维退化 UV 不由这个恒定 UV 修复保证。

## P33 图集位置正确，Canvas copy 却画空

## P34 补画完整，但局部 alpha 仍留下原手掌位置的洞

## P35 图集裁切多加一圈，缩小口型出现采样差异

## P36 嘴网格水平，但张嘴仍显得歪

## P44 alpha 等于 255 的条件可筛空看似不透明的原图

- 复现：v7 侧发遮挡提取初次得到 0 像素；实际可信源发丝 alpha 是 253/254，不是 255。
- 根因：把视觉不透明与编码 alpha=255 混同。空遮挡层若只检查节点存在、lint 通过，会被误认为已恢复遮挡。
- 修正：先测源 alpha 分布，使用声明的可信阈值并保留原像素 alpha；独立 coverage probe 可规范化为二值区域，但不能偷偷把实际素材 alpha 改成同一个数。最小样本数/非空断言必需。
- 回归：纹理确有有效像素；浅/深/透明静态背景，避免重复叠加破坏原透明度；动态遮挡与释放生命周期另验。
- 状态：v7 277 个原侧发像素组成有效前景；生成阶段有非空断言，保留原 alpha，浅/深/透明背景独立复验。可信阈值和 RGB 规则仅用于此角色，不作通用常数。

## P46 闭眼线条直接数学压缩睁眼眼线导致线条生硬失真与眼眶露白【铁律：完整组件严禁手绘/硬捏，必须走图像生成】

- 复现：用户指出表情中的闭眼线条非常奇怪。检查发现笑眼（laugh）呈现为尖锐倒扣的二次抛物线，单眼眨眼（wink）呈现为僵硬水平黑条，且闭眼周围有一圈像眼镜般的浅色眼眶空洞。
- 根因剖析：
  1. **违背生图资产复用原则，试图用代码硬捏眼线**：工程中原本已有通过生图管线产出的高质量闭眼素材（`eyes-closed-generated.png` / `eyes-closed.png`），但旧脚本试图用算法在原有睁眼睫毛上进行 Y 轴单向压缩（`* 0.28`）和二次多项式形变。睁眼眼线原本是向上拱起且带深色阴影的宽厚色块，被强行压扁后像素被压碎，失去了毛尖和粗细渐变，变成了一条死板生硬的“黑胶布条”；笑眼时又强行向上拱起，变成尖锐倒扣的生硬折线。
  2. **闭眼位置浮空**：旧公式将闭眼线锚定在瞳孔中心高度（`closed_y = 267.5`），未下沉至真实的下眼眶（`y = 278`），导致闭眼悬在半空中截断眼窝。
  3. **眼窝衬底错误扣除**：v7 为防止眼白向外扩散，在生成 `eye_underpaint` 时错误地剔除了眼球开孔（`opening`）之外的像素，切除了上眼睑后方 782 处皮肤衬底。闭眼时睫毛下移，眼窝上半部缺少面部皮肤填补，直接露出画布底色形成空洞白圈。
  4. **睫毛素材缺陷**：睁眼睫毛原素材在瞳孔反光处留有像素空洞，左睫毛下方留有紫色瞳孔碎斑，压缩后形成眼线中间断笔与杂色黑痣。
- 修正措施：
  1. **【铁律】完整组件严禁手绘与数学硬捏，必须走图像生成管线**：
     - 闭眼、半闭眼、张嘴等完整新状态组件，严禁代理自行手绘、拼接粗劣色块或用代码算法硬算线条。必须直接接入经生图管线基于唯一定稿生成的透明资产（`eyes-closed-generated.png`），确保睫毛笔触、赛璐珞阴影、眼角飞羽与原画 100% 契合；
     - 闭眼时（`ParamEye*Open = 0`）将开眼睫毛/虹膜淡出、闭眼素材淡入（Sprite Swap），过渡自然平滑；
  2. **恢复全覆盖无缝眼窝皮肤衬底**：`eye_underpaint` 完整覆盖面部眼窝所有切孔，闭眼时由连续饱满的面部皮肤托底，彻底消除白色眼眶空洞与半闭眼露白。
  3. **睫毛素材瑕疵修复**：填补右眼线中间反光穿透空洞，剔除左眼线下方孤立杂色碎片。
- 回归：逐表情特写比较（自然、微笑、笑眼、眨眼、委屈）；眼线厚度与毛尖过渡平滑无断笔，笑眼新月弧甜美舒展，闭眼时与下眼眶完全贴合，面部皮肤 100% 连续无孔洞。
- 状态：v8 已彻底修复并全量验证通过。
