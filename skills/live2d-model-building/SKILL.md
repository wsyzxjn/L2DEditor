# Live2D Model Building

目标是保留用户选定的角色设计，交付能在声明的参数范围内稳定运动、可继续编辑的模型。会动、静态像素对齐、lint 通过、导出成功，都不能单独证明模型完整。

## 开始与分流

1. 读取项目约束，确认唯一认可底稿、源图尺寸、目标编辑器/运行环境、所需动作范围和交付格式。不要自动更换用户选定的软件、画风或角色版本。
2. 先检查现有 PSD、分层素材、变形器、命令、模板、测试和成熟库；复用已有能力。非核心工具不另造一套。截图、图像配准、分层读写、视频编码使用现成工具。
3. 继续旧模型时，先保存可恢复版本并复现缺陷；不要覆盖未保存的编辑器工作。
4. 完整制作读 [workflow.md](references/workflow.md)。动态验收/交付读 [acceptance.md](references/acceptance.md)。碰到缺口、重影、歪嘴或渲染差异读 [pitfalls.md](references/pitfalls.md) 中对应条目，不必一次读完所有参考。
5. 目标是 L2DEditor 时，配合 `$l2deditor-mcp` 使用实际发现的工具，遵守该仓库 AGENTS.md；通用建模原则不替代编辑器真实能力边界。

## 不可省略的建模判断

- **【铁律】完整组件严禁手绘，必须走图像生成**：任何用于 Live2D 拆层、状态替换（如闭眼、半闭眼、张嘴口型、特殊表情）或大面积隐藏补画（如完整躯干、被遮挡后发、去眼去嘴面底）的完整美术组件，**严禁由代理自行手绘、拼接粗劣色块或用代码算法硬算线条**。**必须走图像生成管线**（基于唯一定稿底稿输入，调用 `image_gen` 的 `precise-object-edit` / `inpainting` / `identity-preserve` 模式生成高精度的透明素材），确保笔触质感、线条渐变、赛璐珞阴影与原角色画风 100% 绝对一致。代理与编辑器的职责是网格拓扑、刚性锚点、坐标对齐、透明度过渡与动效求值，而非充当插画师手绘核心美术资产。
- **锁定可见设计**：源图哈希、原始像素坐标、固定画布偏移、眼/嘴/发饰锚点。可见部分优先直接取源图；生成/补画用于缺失和遮挡区域，不借拆层重新设计眼型、发型或比例。
- **先完整部件，再运动**：互斥像素归属只保证原姿态能拼回去。头发、身体、四肢、围巾等必须有合理的隐藏延伸和重叠余量，不能把原来被遮挡的形状当作真正不存在。
- **语义优先**：手指和轮廓不能留在身体/头发层。颜色阈值只作候选，不证明材质或肢体归属；逐层 solo 和动态暴露检查是必需证据。
- **面部局部框架**：口型开合/形状和头部姿态分离。小口型不要被大面积脸部 warp 的剪切拉歪；测嘴中心相对鼻/下巴的漂移及额外滚转，再决定局部锚点、刚性区域和网格密度。
- **可见口型与眼部归属**：水平 UV 轴不等于嘴正；检查底稿脸部的固有倾角和实际口腔轮廓。深色虹膜阴影不能归睫毛，眼白周围皮肤不能随眨眼压缩；眼孔是连续开口，不是部件像素分区的拼图。
- **闭眼与特殊表情优先复用生成素材，禁止程序化硬压睁眼纹理**：二次元角色闭眼并非睁眼睫毛在 Y 轴单向压缩的产物。睁眼睫毛带有厚重眼线、拱起弧度与向上毛尖，硬压只会产生条形码般破碎的僵硬黑杠；强加数学抛物线则导致假笑失真与眼窝露白。工程中已有或由生图管线产出的闭眼/半闭眼/特殊表情素材必须直接复用（通过部件层级覆盖或透明度平滑淡入淡出），保持自然下垂的睫毛羽化、眼角飞翼与双眼皮折痕。严禁自作主张用粗暴算法去硬“算”闭眼线条。
- **参数中间值同样重要**：端点不翻面不代表补间安全；检查组合、连续眨眼、嘴型转换、遮挡顺序和物理滞后。
- **导出闭环**：重新导入、解析、渲染和检查实际目标环境；说明“内部回读通过”与“目标播放器兼容”是不同证据。

## 工作中持续记录

每发现一个新的踩坑，立即在 [pitfalls.md](references/pitfalls.md) 添加或更新：

`症状 → 可复现输入/帧 → 根因与证据 → 修正 → 回归检查 → 状态/残余限制`

区分 `待定位`、`已定位未修`、`已修待验`、`已验证`。未证实的推测不得写成最佳实践或已解决；一般化原则与本角色的坐标、阈值、旧版本结果分开。只记录能改变后续决策的内容，不积累命令输出和重复流水账。

## 完成标准

按 [acceptance.md](references/acceptance.md) 明确通过/失败/未测的门槛，并返回工程、可检查的视频和验证证据。若只完成静态还原、修复部分动作或生成部分包，按阶段报告；不能把整体模型标成完成。
